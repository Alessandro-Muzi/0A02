0A02 — Biblioteca di Alessandro

Deployment automatizzato di Koha ILS · Ansible · Debian 13

Premessa

Mi interessava provare un gestionale per biblioteche, così dopo una rapida ricerca ho scoperto Koha: oltre a essere open source, è l'Integrated Library System più diffuso al mondo, con un ecosistema particolarmente ricco e attivo.

A differenza di 0A01, questo progetto vive su due macchine distinte — un server principale per Koha e i suoi servizi di supporto, e una VM dedicata al monitoraggio, collegate tramite una VPN self-hosted.

Topologia

HostIPRuolo
Server Koha 192.168.1.4 Koha · OpenLDAP · MariaDB · BIND9 · Headscale
VM Zabbix 10.0.0.20 LAN03 · Monitoraggio · Headscale client
Headscale mesh 100.64.0.0/10 VPN self-hosted tra i due nodi

Koha — Deployment Ansible

Installazione e configurazione automatizzata di Koha tramite Ansible, dalla configurazione dei moduli Apache fino all'integrazione LDAP con OpenLDAP.

roles/koha/handlers/main.yml

- name: Riavviare Apache
  ansible.builtin.service:
    name: apache2
    state: restarted

roles/koha/tasks/instance.yml

- name: Abilito il modulo rewrite di Apache
  community.general.apache2_module:
    name: rewrite
    state: present
  notify: Riavviare Apache

- name: Abilito il modulo cgi di Apache
  community.general.apache2_module:
    name: cgi
    state: present
  notify: Riavviare Apache

- name: Verifico se l'istanza Koha esiste
  ansible.builtin.command: koha-list --enabled
  register: koha_instances
  changed_when: false

- name: Creo l'istanza Koha
  ansible.builtin.command: "koha-create --create-db biblioteca"
  when: koha_instance_name not in koha_instances.stdout
  notify: Riavviare Apache

- name: Abilito il sito Koha in Apache
  ansible.builtin.command: "a2ensite biblioteca"
  args:
    creates: /etc/apache2/sites-enabled/biblioteca.conf
  notify: Riavviare Apache

roles/koha/tasks/main.yml

- name: Mi assicuro che la directory dei keyring esista
  ansible.builtin.file:
    path: /etc/apt/keyrings
    state: directory
    mode: '0755'

- name: Scarico la chiave GPG di Koha
  ansible.builtin.get_url:
    url: https://debian.koha-community.org/koha/gpg.asc
    dest: /etc/apt/keyrings/koha-keyring.asc
    mode: '0644'

- name: Aggiungo il repository ufficiale di Koha
  ansible.builtin.apt_repository:
    repo: "deb [signed-by=/etc/apt/keyrings/koha-keyring.asc] https://debian.koha-community.org/koha stable main"
    state: present
    filename: koha
    update_cache: yes

- name: Aggiorno la cache di APT e installo Koha e dipendenze
  ansible.builtin.apt:
    name:
      - koha-common
      - apache2
      - libdbd-mysql-perl
      - libnet-ldap-perl
      - libcrypt-eksblowfish-perl
      - libauthen-sasl-perl
    state: present
    update_cache: yes

- name: Includo i task per la creazione dell'istanza
  ansible.builtin.include_tasks: instance.yml

- name: Configuro l'autenticazione OpenLDAP in koha-conf.xml
  ansible.builtin.blockinfile:
    path: /etc/koha/sites/biblioteca/koha-conf.xml
    marker: ""
    insertbefore: "</config>"
    block: |
      <useldapserver>1</useldapserver>
      <ldapserver id="ldapserver">
        <hostname>{{ ldap_host }}</hostname>
        <port>389</port>
        <base>ou=users,{{ ldap_base_dn }}</base>
        <user>{{ ldap_admin_dn }}</user>
        <pass>{{ ldap_admin_pass }}</pass>
        <replicate>1</replicate>
        <update>1</update>
        <mapping>
          <firstname is="givenName"></firstname>
          <surname is="sn"></surname>
          <address is="postalAddress"></address>
          <email is="mail"></email>
          <branchcode is="branch">MAIN</branchcode>
          <categorycode is="employeetype">PT</categorycode>
          <userid is="uid"></userid>
          <password is="userPassword"></password>
        </mapping>
      </ldapserver>
  notify: Riavviare Apache
Nota: L'attributo is= mappa i campi del form Koha agli attributi LDAP corrispondenti. I valori statici (come MAIN e PT) vengono usati di default se l'attributo LDAP non esiste.

OpenLDAP — Configurazione Ansible

Installazione di OpenLDAP tramite Ansible, con generazione dell'hash della password amministratore e creazione della struttura base del database.

roles/openldap/tasks/main.yml

- name: Installo OpenLDAP e utility di gestione
  ansible.builtin.apt:
    name:
      - slapd
      - ldap-utils
    state: present
    update_cache: yes

- name: Genero l'hash della password amministratore
  ansible.builtin.command: "slappasswd -s {{ ldap_admin_pass }}"
  register: ldap_password_hash
  changed_when: false

- name: Creo il file LDIF temporaneo per la configurazione del database
  ansible.builtin.copy:
    dest: /tmp/db.ldif
    mode: '0600'
    content: |
      dn: olcDatabase={1}mdb,cn=config
      changetype: modify
      replace: olcSuffix
      olcSuffix: {{ ldap_base_dn }}
      -
      replace: olcRootDN
      olcRootDN: {{ ldap_admin_dn }}
      -
      replace: olcRootPW
      olcRootPW: {{ ldap_password_hash.stdout }}

- name: Verifico il valore attuale della configurazione del database
  ansible.builtin.command: >
    ldapsearch -Y EXTERNAL -H ldapi:/// -b "olcDatabase={1}mdb,cn=config"
    -LLL olcSuffix olcRootDN
  register: ldap_current_config
  changed_when: false

- name: Applico la configurazione iniziale del database OpenLDAP
  ansible.builtin.command: ldapmodify -Y EXTERNAL -H ldapi:/// -f /tmp/db.ldif
  when: >
    ldap_base_dn not in ldap_current_config.stdout or
    ldap_admin_dn not in ldap_current_config.stdout

- name: Creo la struttura base (Organizzazione e Gruppo Utenti)
  ansible.builtin.copy:
    dest: /tmp/structure.ldif
    mode: '0600'
    content: |
      dn: {{ ldap_base_dn }}
      objectClass: top
      objectClass: dcObject
      objectClass: organization
      o: {{ ldap_organization }}
      dc: {{ ldap_domain.split('.')[0] }}

      dn: ou=users,{{ ldap_base_dn }}
      objectClass: top
      objectClass: organizationalUnit
      ou: users

- name: Applico la struttura base nel database OpenLDAP
  ansible.builtin.command: "ldapadd -x -D {{ ldap_admin_dn }} -w {{ ldap_admin_pass }} -f /tmp/structure.ldif"
  register: ldap_add_result
  failed_when:
    - ldap_add_result.rc != 0
    - "'Already exists' not in ldap_add_result.stderr"
  changed_when: "'Already exists' not in ldap_add_result.stderr"
Nota: I file LDIF temporanei vengono creati con permessi ristretti (0600) per motivi di sicurezza, poiché contengono la password amministratore. La gestione dei risultati usa failed_when e changed_when per ignorare l'errore "Already exists" — la struttura potrebbe già essere presente da precedenti esecuzioni.

BIND9 — Configurazione DNS

Installazione e configurazione di BIND9 come DNS server locale con zone dirette e inverse, query inoltrate ai DNS pubblici.

roles/bind9/handlers/main.yml

- name: riavvia bind9
  service:
    name: bind9
    state: restarted
    enabled: yes

roles/bind9/tasks/main.yml

- name: Installo Bind9 e strumenti di utilità
  apt:
    name:
      - bind9
      - bind9utils
      - bind9-dnsutils
    state: present
    update_cache: yes

- name: Copio la configurazione principale (options)
  template:
    src: named.conf.options.j2
    dest: /etc/bind/named.conf.options
    owner: root
    group: bind
    mode: '0644'
  notify: riavvia bind9

- name: Copio la configurazione locale (zone)
  template:
    src: named.conf.local.j2
    dest: /etc/bind/named.conf.local
    owner: root
    group: bind
    mode: '0644'
  notify: riavvia bind9

- name: Copio il file della zona diretta
  template:
    src: db.koha.lab.j2
    dest: /etc/bind/db.koha.lab
    owner: root
    group: bind
    mode: '0644'
  notify: riavvia bind9

- name: Copio il file della zona inversa
  template:
    src: db.192.168.1.j2
    dest: /etc/bind/db.192.168.1
    owner: root
    group: bind
    mode: '0644'
  notify: riavvia bind9

- name: Verifica che la configurazione sia corretta
  command: named-checkconf
  changed_when: false

templates/named.conf.options.j2

options {
    directory "/var/cache/bind";

    // Imposta l'IP su cui Bind deve ascoltare
    listen-on { 127.0.0.1; 192.168.1.4; };

    // Sicurezza: solo le reti locali possono fare query
    allow-query { localhost; 192.168.1.0/24; };

    // Inoltra le query sconosciute a questi DNS
    forwarders {
        1.1.1.1;
        8.8.8.8;
    };

    dnssec-validation auto;
    listen-on-v6 { any; };
};

templates/named.conf.local.j2

zone "koha.lab" {
    type master;
    file "/etc/bind/db.koha.lab";
};

// Zona inversa per la subnet 192.168.1.0
zone "1.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/db.192.168.1";
};

templates/db.koha.lab.j2

$TTL 604800
@   IN  SOA ns1.koha.lab. admin.koha.lab. (
            2026070401 ; Serial
            604800     ; Refresh
            86400      ; Retry
            2419200    ; Expire
            604800 )   ; Negative Cache TTL

@       IN  NS  ns1.koha.lab.
ns1     IN  A   192.168.1.4
opac    IN  A   192.168.1.4
intranet IN  A   192.168.1.4

templates/db.192.168.1.j2

$TTL 604800
@   IN  SOA ns1.koha.lab. admin.koha.lab. (
            2026070401 ; Serial
            604800
            86400
            2419200
            604800 )

@       IN  NS  ns1.koha.lab.

; Mapping dell'host (usa l'ultimo ottetto dell'IP, es. 4)
4      IN  PTR ns1.koha.lab.
4      IN  PTR opac.koha.lab.
4      IN  PTR intranet.koha.lab.
Nota: Le zone dirette e inverse sono configurate come master. Il Serial deve essere incrementato manualmente ogni volta che il file della zona viene modificato, altrimenti i nameserver secondari (se presenti) non sincronizzeranno i cambiamenti.

Headscale — VPN Mesh Ansible

Installazione di Headscale come server VPN self-hosted e configurazione dei client Tailscale per la connessione alla mesh.

Headscale Server

roles/headscale/defaults/main.yml

# Dominio pubblico (o interno) su cui sarà raggiungibile Headscale
headscale_server_url: "https://192.168.1.4:8443"

# Porta di ascolto interna di Headscale
headscale_listen_port: 8443

# Percorso base dei dati e della configurazione
headscale_config_dir: /etc/headscale
headscale_data_dir: /var/lib/headscale

# Range IP della tailnet (default Tailscale/Headscale)
headscale_ip_prefix_v4: "100.64.0.0/10"

# Nome utente/namespace di default
headscale_default_user: homelab

# Base domain per MagicDNS
headscale_base_domain: "lab.internal"

roles/headscale/handlers/main.yml

- name: riavvia headscale
  ansible.builtin.systemd:
    name: headscale
    state: restarted

roles/headscale/tasks/main.yml

- name: Scarica il pacchetto .deb di Headscale dalla release GitHub
  ansible.builtin.get_url:
    url: "https://github.com/juanfont/headscale/releases/download/v{{ headscale_version }}/headscale_{{ headscale_version }}_linux_amd64.deb"
    dest: /tmp/headscale_{{ headscale_version }}.deb
    mode: '0644'
  register: headscale_download

- name: Installa il pacchetto Headscale
  ansible.builtin.apt:
    deb: /tmp/headscale_{{ headscale_version }}.deb
    state: present
  when: headscale_download is changed

- name: Crea le directory dati e configurazione
  ansible.builtin.file:
    path: "{{ item }}"
    state: directory
    owner: headscale
    group: headscale
    mode: '0750'
  loop:
    - "{{ headscale_config_dir }}"
    - "{{ headscale_data_dir }}"

- name: Distribuisci il file di configurazione config.yaml
  ansible.builtin.template:
    src: config.yaml.j2
    dest: {{ headscale_config_dir }}/config.yaml
    owner: headscale
    group: headscale
    mode: '0640'
  notify: riavvia headscale

- name: Abilita e avvia il servizio headscale
  ansible.builtin.systemd:
    name: headscale
    state: started
    enabled: true

- name: Verifica se l'utente di default esiste già
  ansible.builtin.command: "headscale users list --output json"
  register: headscale_users_list
  changed_when: false

- name: Crea l'utente/namespace di default nella tailnet
  ansible.builtin.command: "headscale users create {{ headscale_default_user }}"
  when: headscale_default_user not in headscale_users_list.stdout
  register: headscale_user_create
  changed_when: headscale_user_create.rc == 0

roles/headscale/templates/config.yaml.j2

server_url: {{ headscale_server_url }}
listen_addr: 0.0.0.0:{{ headscale_listen_port }}  # NON 127.0.0.1: vedi troubleshooting
metrics_listen_addr: 127.0.0.1:9090

private_key_path: {{ headscale_data_dir }}/private.key
noise:
  private_key_path: {{ headscale_data_dir }}/noise_private.key  # Path in /var/lib, non /etc

prefixes:
  v4: {{ headscale_ip_prefix_v4 }}

derp:
  server:
    enabled: false
  urls:
    - https://controlplane.tailscale.com/derpmap/default
  auto_update_enabled: true
  update_frequency: 24h

disable_check_updates: true

database:
  type: sqlite
  sqlite:
    path: {{ headscale_data_dir }}/db.sqlite

log:
  level: info

dns:
  magic_dns: true
  base_domain: {{ headscale_base_domain }}
  nameservers:
    global:
      - 1.1.1.1
      - 9.9.9.9

Headscale Client (Tailscale)

roles/headscale-client/defaults/main.yml

headscale_login_server: "http://192.168.1.4:8443"
headscale_preauth_key: "{{ vault_headscale_preauth_key }}"

roles/headscale-client/handlers/main.yml

- name: Aggiorna cache apt
  ansible.builtin.apt:
    update_cache: true

roles/headscale-client/tasks/main.yml

- name: Installa dipendenze per il repository Tailscale
  ansible.builtin.apt:
    name:
      - curl
      - gnupg
    state: present
    update_cache: true

- name: Aggiungi la chiave GPG del repository Tailscale
  ansible.builtin.get_url:
    url: https://pkgs.tailscale.com/stable/debian/trixie.noarmor.gpg
    dest: /usr/share/keyrings/tailscale-archive-keyring.gpg
    mode: '0644'

- name: Aggiungi il repository APT di Tailscale
  ansible.builtin.get_url:
    url: https://pkgs.tailscale.com/stable/debian/trixie.tailscale-keyring.list
    dest: /etc/apt/sources.list.d/tailscale.list
    mode: '0644'
  notify: Aggiorna cache apt

- name: Applica subito gli handler in sospeso
  ansible.builtin.meta: flush_handlers

- name: Installa il pacchetto tailscale
  ansible.builtin.apt:
    name: tailscale
    state: present
    update_cache: true

- name: Abilita e avvia il servizio tailscaled
  ansible.builtin.systemd:
    name: tailscaled
    state: started
    enabled: true

- name: Verifica lo stato attuale della connessione tailscale
  ansible.builtin.command: tailscale status --json
  register: tailscale_status
  changed_when: false
  failed_when: false

- name: Connetti il nodo alla tailnet Headscale tramite preauth key
  ansible.builtin.command: >
    tailscale up
    --login-server={{ headscale_login_server }}
    --authkey={{ headscale_preauth_key }}
    --accept-routes
  register: tailscale_up_result
  changed_when: "'Success' in tailscale_up_result.stdout or tailscale_up_result.rc == 0"
  when: >
    tailscale_status.rc != 0 or
    '"BackendState":"Running"' not in tailscale_status.stdout
Nota: La preauth key è memorizzata in vault e permette ai client di unirsi automaticamente alla tailnet Headscale senza intervento manuale. Il file config.yaml.j2 richiede ProtectSystem=strict nel systemd unit, quindi i dati vanno in /var/lib, non in /etc.

Zabbix — Server di Monitoraggio Ansible

Installazione di Zabbix server con MariaDB, frontend PHP, e agenti di monitoraggio. Configurazione automatizzata via Ansible con gestione dello schema SQL iniziale.

roles/zabbix-server/defaults/main.yml

zabbix_version: "7.0"
# Nome in codice della release Debian (es. "trixie", "bookworm")
zabbix_debian_release: "trixie"

zabbix_db_name: zabbix
zabbix_db_user: zabbix
zabbix_db_password: "1234"

zabbix_server_listen_port: 10051
zabbix_frontend_timezone: "Europe/Rome"

# Se true, il ruolo importa lo schema SQL iniziale (solo al primo run)
zabbix_import_schema: true

roles/zabbix-server/handlers/main.yml

- name: Riavviare Zabbix server
  ansible.builtin.systemd:
    name: zabbix-server
    state: restarted

- name: Riavviare Apache
  ansible.builtin.systemd:
    name: apache2
    state: restarted

roles/zabbix-server/tasks/main.yml

- name: Installa dipendenze base (gnupg per repository esterni)
  ansible.builtin.apt:
    name: gnupg
    state: present
    update_cache: true

- name: Scarica la chiave GPG ufficiale di Zabbix
  ansible.builtin.get_url:
    url: https://repo.zabbix.com/zabbix-official-repo.key
    dest: /usr/share/keyrings/zabbix-official-repo.key
    mode: '0644'

- name: Aggiungi il repository APT di Zabbix
  ansible.builtin.apt_repository:
    repo: "deb [signed-by=/usr/share/keyrings/zabbix-official-repo.key] https://repo.zabbix.com/zabbix/{{ zabbix_version }}/debian {{ zabbix_debian_release }} main"
    state: present
    filename: zabbix

- name: Aggiorna la cache apt dopo l'aggiunta del repository Zabbix
  ansible.builtin.apt:
    update_cache: true

- name: Installa MariaDB server
  ansible.builtin.apt:
    name:
      - mariadb-server
      - python3-pymysql
    state: present

- name: Abilita e avvia MariaDB
  ansible.builtin.systemd:
    name: mariadb
    state: started
    enabled: true

- name: Installa Zabbix server, frontend e agent
  ansible.builtin.apt:
    name:
      - zabbix-server-mysql
      - zabbix-frontend-php
      - zabbix-apache-conf
      - zabbix-sql-scripts
      - zabbix-agent2
    state: present

- name: Crea il database Zabbix
  community.mysql.mysql_db:
    name: "{{ zabbix_db_name }}"
    encoding: utf8mb4
    collation: utf8mb4_bin
    state: present
    login_unix_socket: /run/mysqld/mysqld.sock

- name: Crea l'utente MariaDB per Zabbix
  community.mysql.mysql_user:
    name: "{{ zabbix_db_user }}"
    password: "{{ zabbix_db_password }}"
    priv: "{{ zabbix_db_name }}.*:ALL"
    login_unix_socket: /run/mysqld/mysqld.sock
    state: present

- name: Verifica se lo schema Zabbix è già stato importato
  ansible.builtin.command: >
    mysql -u{{ zabbix_db_user }} -p{{ zabbix_db_password }} {{ zabbix_db_name }}
    -e "SHOW TABLES LIKE 'users';"
  register: zabbix_schema_check
  changed_when: false
  failed_when: false

- name: Importa lo schema SQL iniziale di Zabbix (solo al primo run)
  ansible.builtin.shell: >
    zcat /usr/share/zabbix-sql-scripts/mysql/server.sql.gz |
    mysql -u{{ zabbix_db_user }} -p{{ zabbix_db_password }} {{ zabbix_db_name }}
  when:
    - zabbix_import_schema
    - "'users' not in zabbix_schema_check.stdout"
  register: zabbix_schema_import
  changed_when: zabbix_schema_import.rc == 0

- name: Configura DBPassword in zabbix_server.conf
  ansible.builtin.lineinfile:
    path: /etc/zabbix/zabbix_server.conf
    regexp: '^# ?DBPassword='
    line: "DBPassword={{ zabbix_db_password }}"
  notify: Riavviare Zabbix server

- name: Configura il timezone nel frontend PHP di Zabbix
  ansible.builtin.lineinfile:
    path: /etc/zabbix/apache.conf
    regexp: php_value date.timezone
    line: "        php_value date.timezone {{ zabbix_frontend_timezone }}"
  notify: Riavviare Apache

- name: Abilita e avvia Zabbix server
  ansible.builtin.systemd:
    name: zabbix-server
    state: started
    enabled: true

- name: Abilita e avvia Zabbix agent2
  ansible.builtin.systemd:
    name: zabbix-agent2
    state: started
    enabled: true

- name: Riavvia Apache per applicare la configurazione Zabbix
  ansible.builtin.systemd:
    name: apache2
    state: restarted
Nota: Lo schema SQL viene importato solo al primo run (controllo sulla presenza della tabella users). La password di default "1234" deve essere sostituita con un valore casuale memorizzato in vault. Frontend raggiungibile via Apache dopo il riavvio.
